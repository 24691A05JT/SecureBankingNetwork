# Wireshark Network Packet Analysis Guide
**Project:** SecureBankingNetwork  
**Module:** Day 13 Network Verification & Traffic Analysis  

---

## 1. Overview
This document provides an exact operational guide for capturing, filtering, and analyzing real TCP packet streams generated by the **SecureBankingNetwork** transaction pipeline. 

The application utilizes Java TCP `Socket` and `ServerSocket` communication over localhost (`127.0.0.1`) with length-prefixed framing and AES-256-GCM payload encryption.

---

## 2. Step-by-Step Wireshark Capture Procedure

### Step 1: Launch Wireshark
Open Wireshark on your host operating system (Windows / Linux / macOS).

### Step 2: Select Loopback Capture Interface
Because the application transmits traffic over `127.0.0.1` (localhost):
- **Windows**: Select **Npcap Loopback Adapter** or **Adapter for loopback traffic capture**.
- **Linux / macOS**: Select the **lo** or **loopback** interface.

> [!NOTE]
> Standard Ethernet or Wi-Fi adapters will not capture internal `127.0.0.1` traffic on Windows unless Npcap loopback driver is selected.

### Step 3: Start Packet Capture
Click the blue shark fin icon or double-click the loopback interface to begin live capture.

### Step 4: Run the Application
In your terminal or IDE, execute the TCP pipeline demonstration or launch the JavaFX Dashboard:

```powershell
mvn exec:java -Dexec.mainClass="com.banking.Main"
```

Watch the console output for the diagnostic target log line:
```text
[INFO] TCP_CAPTURE_TARGET=127.0.0.1:49753
```

### Step 5: Stop Packet Capture
Once the transaction output or dashboard confirmation appears, click the red square **Stop Capture** button in Wireshark.

### Step 6: Apply Port Display Filter
Filter the captured traffic by entering the actual port logged by the application into the Wireshark display filter bar:

```text
tcp.port == 49753
```
*(Replace `49753` with the actual runtime port printed in your application log).*

## 3. Recommended Wireshark Display Filters

| Filter Expression | Purpose |
| :--- | :--- |
| `tcp` | Filters all TCP protocol packets |
| `tcp.port == <PORT>` | Filters traffic on the dynamically bound server port |
| `ip.addr == 127.0.0.1` | Restricts traffic to IPv4 localhost loopback |
| `tcp.flags.syn == 1` | Isolates connection initiation requests |
| `tcp.flags.fin == 1` | Isolates connection termination packets |
| `tcp.stream` | Right-click any packet and select **Follow -> TCP Stream** to view raw packet bytes |

## 4. Wireshark Verification Checklist

### A. Connection Establishment (TCP Three-Way Handshake)
Verify the initial socket connection setup:
1. **`[SYN]`**: Client sends SYN packet to server port `<PORT>`.
2. **`[SYN, ACK]`**: Server responds with SYN-ACK to client port.
3. **`[ACK]`**: Client acknowledges server response.

### B. Application Data Transmission
1. Locate TCP segment containing application data (`PSH, ACK` flags set).
2. Verify 4-byte big-endian integer length prefix preceding payload bytes.
3. Confirm length matches transmitted byte count logged by `BankingClient` and `BankingServer`.

### C. Connection Termination (TCP Four-Way Teardown)
Verify clean release of network resources:
1. **`[FIN, ACK]`**: Client/Server initiates graceful socket close.
2. **`[ACK]`**: Receiver acknowledges FIN.
3. **`[FIN, ACK]`**: Receiver closes socket direction.
4. **`[ACK]`**: Final acknowledgment.

### D. Confidentiality Verification (AES-256-GCM Encryption)
Inspect the raw TCP application payload bytes:
- **Observed Data**: Base64-encoded AES-256-GCM ciphertext and 12-byte IV (`MgdsFMCWiS2JcVD...::kGQgz3TWR+94...::CRC=0x9581`).
- **Verified Protection**: Account numbers (`ACC10001`, `ACC10002`), transfer amounts (`₹5000.00`), and transaction IDs do **NOT** appear as plain human-readable text on the wire.
